# 03 树与二叉树

> 本篇导读：树形结构在数据库、文件系统、索引里无处不在。本篇讲清二叉树遍历、二叉搜索树，以及面试高频的平衡树（AVL、红黑树）、B/B+ 树、堆，建立"为什么需要平衡"的直觉。

## 一、树的基本概念

数组是线性的，链表也是线性的。一旦数据之间出现"一对多"的层级关系（比如公司的组织架构、文件目录、人事审批流），线性结构就表达不出来了。树（Tree）就是专门描述这种**层级 / 分支**关系的非线性结构。

### 1.1 基本术语

先看一棵最朴素的总览：

```text
            [ A ]                  <- 根节点 root
           /     \
        [ B ]     [ C ]            <- 内部节点
       /   \         \
    [ D ] [ E ]     [ F ]          <- D、E、F 是叶子
```

术语一张表讲清：

| 术语 | 含义 | 上图对应 |
| --- | --- | --- |
| **节点（Node）** | 树中的元素 | A、B、C、D、E、F |
| **根（Root）** | 没有父节点的节点 | A |
| **叶子（Leaf）** | 没有子节点的节点 | D、E、F |
| **父 / 子（Parent / Child）** | 上下相邻的两层 | B 是 D 的父，D 是 B 的子 |
| **兄弟（Sibling）** | 同一父亲的孩子 | D 与 E 是兄弟 |
| **度（Degree）** | 一个节点的**直接孩子数量** | A 的度为 2，B 的度为 2，D 的度为 0 |
| **深度 / 层（Depth / Level）** | 从根往下数第几层（根算第 1 层，深度=层号-1） | D 在第 3 层，深度为 2 |
| **高度（Height）** | 从某节点到最远叶子的最长路径边数 | A 高度为 2，D 高度为 0 |

一个有意思的约定：**节点的深度是从根"往下"数的距离，节点的高度是从该节点"往上"到根的距离的反向版本**。树的高度 = 根的高度 = 所有叶子深度的最大值。这两个概念面试常考，记一句：**深度看根，高度看叶**。

### 1.2 二叉树 vs 多叉树

- **二叉树（Binary Tree）**：每个节点**最多**有 2 个孩子（左孩子、右孩子，左右有序）。
- **多叉树（N-ary Tree / K-ary Tree）**：每个节点可以有 k 个孩子，例如 B 树、Trie（字典树）、文件系统目录。

为什么这么多结构都用二叉树打底？因为二叉的结构最简单、递归性质最好，几乎所有树算法都能写成"处理当前节点 + 递归处理左右子树"。多叉树往往也能通过"左孩子右兄弟"表示法压成二叉树来存。

### 1.3 两种特殊的二叉树

| 类型 | 定义 | 直观特征 |
| --- | --- | --- |
| **满二叉树（Full Binary Tree）** | 每一层的节点数都达到该层最大值（即每个内部节点都有 2 个孩子，且所有叶子在同一层） | 形状"完美饱满" |
| **完全二叉树（Complete Binary Tree）** | 除最后一层外全满，最后一层从左到右连续填充、不能有"空档" | 适合用数组顺序存储 |

```text
满二叉树：              完全二叉树（非满）：
        [1]                    [1]
       /   \                  /   \
     [2]   [3]             [2]   [3]
    / \   / \             / \   /
  [4][5][6][7]         [4][5][6]
（最后一层全满）        （最后一层左侧连续，右侧空）
```

完全二叉树是后面"堆"和"用数组存树"的地基，**必须分清它和满二叉树的区别**：满二叉树一定是完全的，但完全二叉树不一定满。

## 二、二叉树性质

以下性质是选择题和手写推导的常客，建议直接背熟并会证明。设二叉树中节点总数为 n，叶子数为 `n0`，度为 1 的节点数为 `n1`，度为 2 的节点数为 `n2`。

**性质 1：第 i 层最多有 `2^(i-1)` 个节点**（i 从 1 开始）。

> 根层 1 个，第二层最多 2 个，第三层最多 4 个……逐层翻倍，等比数列求和即得。

**性质 2：深度为 k 的二叉树最多有 `2^k - 1` 个节点**。

> 把每一层最大值加起来：`1 + 2 + 4 + ... + 2^(k-1) = 2^k - 1`。这也正好是一棵深度为 k 的满二叉树的节点总数。

**性质 3（最关键）：任意二叉树中，叶子数 = 度为 2 的节点数 + 1，即 `n0 = n2 + 1`**。

证明（用边计数）：

- 总节点数：`n = n0 + n1 + n2`。
- 总边数：每个节点（除根）都有一条边连向父节点，所以边数 = `n - 1`。
- 另一方面，每条边来自某个有孩子的节点：度为 1 贡献 1 条边，度为 2 贡献 2 条边，度为 0 贡献 0 条。故边数 = `n1 + 2*n2`。
- 于是 `n - 1 = n1 + 2*n2`，代入 `n = n0 + n1 + n2`：`n0 + n1 + n2 - 1 = n1 + 2*n2` → `n0 - 1 = n2` → **`n0 = n2 + 1`**。

**性质 4：有 n 个节点的完全二叉树，深度为 `⌊log2(n)⌋ + 1`**（以 2 为底取整）。

> 由性质 2 反推：深度为 k 的满树有 `2^k - 1` 个节点，所以 `2^(k-1) - 1 < n <= 2^k - 1`，解得 k = `⌊log2(n)⌋ + 1`。

**性质 5（完全二叉树父子的数组下标关系）**：若节点按层序从 1 开始编号，则节点 i 的左孩子为 `2i`、右孩子为 `2i+1`、父节点为 `⌊i/2⌋`。这条直接支撑了"用数组存完全二叉树"。

一张速查表：

| 性质 | 公式 |
| --- | --- |
| 第 i 层最大节点数 | `2^(i-1)` |
| 深度 k 最大节点数 | `2^k - 1` |
| 叶子与度为 2 节点 | `n0 = n2 + 1` |
| n 节点完全二叉树深度 | `⌊log2(n)⌋ + 1` |

## 三、二叉树的存储

二叉树的存储只有两条主流路线：**顺序存储（数组）**和**链式存储（指针 / 引用）**。

### 3.1 顺序存储：数组

只适合**完全二叉树**。把节点按层序从下标 1（或 0）开始依次塞进数组，利用性质 5 父子互算。

```text
完全二叉树：       数组（下标从 1 起）：
      [1]          index: 1  2  3  4  5  6
     /   \          value: 1  2  3  4  5  6
   [2]   [3]
  / \   /          父子关系：2 的孩子是 4,5；3 的孩子是 6
[4][5][6]
```

优点：不需要额外指针，**父子跳转是 O(1) 的下标计算**，Cache 友好。缺点：如果不是完全二叉树，中间要补大量"空洞"占位，空间浪费严重。所以**堆**几乎都用数组存。

若从下标 0 起编号，则节点 i 的左孩子是 `2i+1`、右孩子 `2i+2`、父节点 `⌊(i-1)/2⌋`——这是 Java `PriorityQueue` 的实现口径。

### 3.2 链式存储：左右指针

通用做法，每个节点带数据 + 左指针 + 右指针：

```java
package cn.canoe.dsa.tree;

/** 二叉树节点（链式存储）。 */
public class TreeNode {
    int val;
    TreeNode left;
    TreeNode right;

    TreeNode(int val) {
        this.val = val;
    }
}
```

对于一般的、非完全的二叉树，链式是唯一不浪费空间的方案。缺点是多了两个指针的额外开销，且由于节点在堆上分散分布，Cache 命中率不如数组。

两种存储对比：

| 维度 | 顺序（数组） | 链式（指针） |
| --- | --- | --- |
| 适用形状 | 完全二叉树（堆） | 任意二叉树 |
| 空间 | 紧凑、无指针开销 | 每节点 2 个指针开销 |
| 父子访问 | O(1) 下标计算 | 跟随指针 O(1) |
| Cache 友好度 | 高（连续内存） | 低（跳来跳去） |

## 四、遍历

遍历是二叉树的灵魂。所谓遍历，就是**按某种固定顺序，不重不漏地把每个节点访问一遍**。四类遍历的本质区别在于"访问根"的时机。

### 4.1 前序 / 中序 / 后序（递归定义）

三者都由"左子树一定在右子树之前"统一约束，差别只在根的位置：

| 遍历 | 访问顺序 | 助记 |
| --- | --- | --- |
| **前序（Pre-order）** | 根 → 左 → 右 | 根在最前 |
| **中序（In-order）** | 左 → 根 → 右 | 根在中间 |
| **后序（Post-order）** | 左 → 右 → 根 | 根在最后 |

对下面这棵树手推三种序列：

```text
          [ 1 ]
         /     \
      [ 2 ]   [ 3 ]
     /   \       \
   [ 4 ] [ 5 ]   [ 6 ]
```

- **前序**：先 1，再整棵左子树（先 2，再 4，再 5），最后右子树（3，6）→ `1 2 4 5 3 6`
- **中序**：左子树中序（4，2，5），根 1，右子树中序（3 的左右：先空、3、6）→ `4 2 5 1 3 6`
- **后序**：左子树后序（4，5，2），右子树后序（6，3），根 1 → `4 5 2 6 3 1`

**一个关键直觉**：中序遍历对**二叉搜索树**来说会得到**升序序列**，这是 BST 最重要的性质之一，后面验证树是否合法、做范围查询都靠它。

### 4.2 递归实现（思路最清晰）

```java
package cn.canoe.dsa.tree;

import java.util.ArrayList;
import java.util.List;

public class Traversal {

    /** 前序：根 -> 左 -> 右 */
    void preorder(TreeNode root, List<Integer> out) {
        if (root == null) return;
        out.add(root.val);        // 1) 访问根
        preorder(root.left, out); // 2) 递归左
        preorder(root.right, out);// 3) 递归右
    }

    /** 中序：左 -> 根 -> 右 */
    void inorder(TreeNode root, List<Integer> out) {
        if (root == null) return;
        inorder(root.left, out);
        out.add(root.val);
        inorder(root.right, out);
    }

    /** 后序：左 -> 右 -> 根 */
    void postorder(TreeNode root, List<Integer> out) {
        if (root == null) return;
        postorder(root.left, out);
        postorder(root.right, out);
        out.add(root.val);
    }
}
```

递归版本之所以好写，是因为它把"保存现场 / 恢复现场"交给了**函数调用栈**。递归深度等于树高，最坏（链状树）会到 O(n)，可能栈溢出——所以懂迭代写法很重要。

### 4.3 迭代实现（显式栈）

以前序为例，用显式栈模拟递归。核心技巧：**因为栈是后进先出，想让左子树先出，就要先把右孩子压栈，再把左孩子压栈**。

```java
package cn.canoe.dsa.tree;

import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.List;

public class PreorderIter {
    List<Integer> preorder(TreeNode root) {
        List<Integer> out = new ArrayList<>();
        if (root == null) return out;
        ArrayDeque<TreeNode> stack = new ArrayDeque<>();
        stack.push(root);
        while (!stack.isEmpty()) {
            TreeNode n = stack.pop();
            out.add(n.val);              // 访问根
            if (n.right != null) stack.push(n.right); // 右后出，先压
            if (n.left != null) stack.push(n.left);   // 左先出，后压
        }
        return out;
    }
}
```

中序遍历的迭代套路不同：先一路把左孩子压栈到底，弹出时访问，再转向右子树。后序可以用"前序变形（根→右→左）再反转"或"双栈"实现，思路一致。

### 4.4 层序遍历（BFS）

层序是**广度优先**，借助队列一层一层扫，和"前中后序"（深度优先）完全不同：

```java
package cn.canoe.dsa.tree;

import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.List;

public class LevelOrder {
    List<List<Integer>> levelOrder(TreeNode root) {
        List<List<Integer>> result = new ArrayList<>();
        if (root == null) return result;
        ArrayDeque<TreeNode> queue = new ArrayDeque<>();
        queue.offer(root);
        while (!queue.isEmpty()) {
            int size = queue.size();        // 当前层节点数
            List<Integer> level = new ArrayList<>();
            for (int i = 0; i < size; i++) {
                TreeNode n = queue.poll();
                level.add(n.val);
                if (n.left != null) queue.offer(n.left);
                if (n.right != null) queue.offer(n.right);
            }
            result.add(level);
        }
        return result;
    }
}
```

上面那棵树的层序结果是：`[[1], [2, 3], [4, 5, 6]]`，每一层打包成一个列表，这是很多"按层处理"题目的标准输出格式。

### 4.5 由遍历序列还原二叉树

一句话：**只给前序/后序无法唯一确定一棵树，但"前序 + 中序"或"后序 + 中序"可以唯一还原**（前提节点值不重复）。原理是：前/后序提供"根是谁"，中序用根把序列切成左右两部分，再递归构造。这道"从中序与后序遍历构造二叉树"是 LeetCode 106 原题。

## 五、二叉搜索树 BST

二叉搜索树（Binary Search Tree，BST）在二叉树基础上加了一条**排序规则**，让"查找"变得高效。

### 5.1 定义：左小右大

对任意节点，其**左子树所有节点值 < 当前值 < 右子树所有节点值**。因此，**中序遍历 BST 必得升序序列**——这是判断一棵二叉树是否合法的天然校验。

```text
         [ 8 ]
        /     \
     [ 3 ]   [ 10 ]
    /   \       \
  [ 1 ] [ 6 ]   [ 14 ]
          /     /
        [ 4 ] [ 13 ]
```

上图满足：3 的左 <3< 右(6)；6 的左(4)<6；10 的右子树全 >10。符合要求。

### 5.2 查找、插入、删除

**查找**：从根出发，目标比当前小走左、比当前大走右，相等即命中，走到空说明不存在。每次下降一层，所以时间复杂度与树高相关。

```java
package cn.canoe.dsa.tree;

public class BstSearch {
    TreeNode search(TreeNode root, int key) {
        TreeNode cur = root;
        while (cur != null) {
            if (key == cur.val) return cur;
            cur = (key < cur.val) ? cur.left : cur.right;
        }
        return null; // 没找到
    }
}
```

**插入**：先按查找的路径走到"该落下的空位"，再把新节点挂上去。重复值通常放右子树或忽略（按实现而定）。

**删除**：最麻烦，分三种情况：

| 情况 | 处理 |
| --- | --- |
| 删除节点是叶子 | 直接摘除 |
| 只有一个孩子 | 用孩子顶替它的位置 |
| 有两个孩子 | 找**中序后继**（右子树的最小节点）或**中序前驱**（左子树的最大节点）顶替，再递归删掉那个顶替节点 |

### 5.3 退化的 O(n) 问题

BST 的性能完全取决于**树是否平衡**。如果依次插入一个已经有序的序列 `1,2,3,4,5,6`，会得到一条向右的链：

```text
[1]
  \
  [2]
    \
    [3]
      \
      [4] ... 退化成链表
```

此时查找退化为 O(n)，和链表没区别。**根因：BST 没有任何机制保证左右子树平衡**。这个问题催生了 AVL 树和红黑树——它们给 BST 加了"平衡约束"，把树高始终压在 O(log n)。这正是本篇后续要讲的内容。

## 六、平衡二叉树 AVL

AVL 树（以发明者 Adelson-Velsky 和 Landis 命名）是**第一个自平衡二叉搜索树**。核心思想：给每个节点定义"平衡因子"，一旦失衡就通过**旋转**把它拉回来。

### 6.1 平衡因子与平衡条件

对每个节点，**平衡因子 = 左子树高度 - 右子树高度**。AVL 要求**所有节点的平衡因子 ∈ {-1, 0, +1}**。只要插入/删除后某个节点的平衡因子变成 ±2，就触发旋转修复。

这意味着 AVL 的树高始终约为 `1.44 * log2(n)`，查找复杂度严格 **O(log n)**，最坏情况也被锁死。

### 6.2 四种旋转

失衡有四种形态，对应四种旋转。记法：字母表示"从失衡节点往下，路径偏向"。

| 失衡类型 | 形状特征 | 旋转动作 |
| --- | --- | --- |
| **LL** | 新节点插在**左子树的左**侧 | 对失衡节点做**右旋** |
| **RR** | 新节点插在**右子树的右**侧 | 对失衡节点做**左旋** |
| **LR** | 新节点插在**左子树的右**侧 | 先左旋左孩子，再右旋失衡节点 |
| **RL** | 新节点插在**右子树的左**侧 | 先右旋右孩子，再左旋失衡节点 |

旋转的本质是**在不破坏 BST 中序有序性的前提下，把较高的那一侧"压"下来、较矮的一侧"抬"上去**，让局部重新平衡。

### 6.3 用 ASCII 图展示一次左旋（RR 情形）

场景：节点 y 失衡，右子树太高。对 y 做**左旋**，让它的右孩子 x 上位，y 变成 x 的左孩子。

左旋前：

```text
        [ y ]                y 失衡（平衡因子 = -2）
          \
          [ x ]              x 是 y 的右孩子
          /
        [ xL ]               x 的左子树
```

左旋后（以 x 为轴，y 下沉为 x 的左孩子，x 的原左子树 xL 成为 y 的右孩子）：

```text
        [ x ]
        /
      [ y ]
        \
       [ xL ]
```

对应的代码骨架（右旋是镜像，不再赘述）：

```java
package cn.canoe.dsa.tree;

/** AVL 左旋：返回旋转后的新子树根。 */
public class AvlRotate {
    TreeNode rotateLeft(TreeNode y) {
        TreeNode x = y.right;
        TreeNode xL = x.left;

        // 1) x 上位，y 变成 x 的左孩子
        x.left = y;
        // 2) x 原来的左子树挂到 y 的右边
        y.right = xL;

        // 3) 重新计算高度（由实现决定是否在此更新）
        return x; // x 成为这棵子树的新根
    }
}
```

> 注意：真实 AVL 实现里每个节点还要维护 `height` 字段，旋转后必须自下而上更新受影响的节点高度，再据平衡因子决定是否继续向上回溯修复。

### 6.4 为什么是 O(log n)

因为 AVL 强制树高 `h <= 1.44 * log2(n)`，所以查找、插入、删除的每一步都只走 O(h) = O(log n) 层。代价是：插入/删除后可能要沿路径一路回溯做多次旋转来恢复平衡，**写操作比普通 BST 重**，但读操作极快、且最差情况确定。适合**读多写少、且对查询延迟有确定性要求**的场景。

## 七、红黑树

红黑树（Red-Black Tree）是另一种自平衡 BST，但它**不追求像 AVL 那样严格平衡**，而是用"颜色 + 几条规则"维持**近似平衡**。结果是：查找稍慢于 AVL，但插入删除的旋转次数少得多。

### 7.1 五条性质

每个节点要么红要么黑，且满足：

1. 节点非红即黑。
2. 根节点是**黑色**。
3. 所有**叶子（NIL 空节点）是黑色**。
4. **红色节点的两个孩子都必须是黑色**（即**不能有连续的红节点**，红红不相邻）。
5. 从任一节点到其所有后代叶子的**每条路径上，黑色节点数量相同**（黑高一致）。

性质 4 + 性质 5 共同保证：最长路径（红黑交替）不超过最短路径（全黑）的 **2 倍**，所以树高最坏也是 O(log n)，但允许比 AVL 更"扁"一些。

```text
         (B)8                 B=黑 R=红
        /     \
     (R)3     (B)10
    /   \         \
  (B)1 (B)6      (R)14
```

上图中根 8 为黑、红 3 的两个孩子都是黑、各路径黑高一致（都含 8、10... 具体以实现为准），满足红黑性质。

### 7.2 与 AVL 的对比

| 维度 | AVL | 红黑树 |
| --- | --- | --- |
| 平衡严格度 | 严格（平衡因子 ±1） | 近似（最长 ≤ 2×最短） |
| 树高 | 更矮 | 略高 |
| 查找速度 | 更快 | 略慢 |
| 插入/删除旋转次数 | 可能多次，较重 | 最多 2 次旋转，较轻 |
| 适合场景 | 读多写少 | 读写均衡、频繁增删 |

### 7.3 典型应用

- **Java `TreeMap` / `TreeSet`**：底层就是红黑树，提供有序的 key 操作和 `O(log n)` 的增删查。
- **Java 8 `HashMap`**：当桶（bucket）冲突链表长度 ≥ 8 且表容量 ≥ 64 时，链表转为红黑树，把最坏查找从 O(n) 拉回 O(log n)。
- **Linux 的 `epoll`**：就绪事件用红黑树管理，便于 O(log n) 增删查 fd。
- **Linux 进程调度（CFS）**：完全公平调度器用红黑树按"虚拟运行时间"组织可运行进程。
- **C++ `std::map` / `std::set`**（通常实现为红黑树）。

一句话：**凡是需要"有序 + 频繁增删 + 稳定 O(log n)"的地方，红黑树几乎都是默认答案**。

## 八、B 树与 B+ 树

当数据量大到**内存装不下、必须落磁盘**时，二叉搜索树就不够看了——因为树高还是 O(log n)，但每次下钻都要一次磁盘 IO，而磁盘 IO 比内存慢几个数量级。B 树 / B+ 树通过**让每个节点装很多 key、大幅降低树高**来减少 IO，是数据库和文件系统的基石。

### 8.1 m 阶 B 树的定义

一棵 **m 阶 B 树**满足：

1. 每个节点**最多 m 个孩子**，最多 `m-1` 个关键字。
2. 除根和叶子外，每个节点**至少 `⌈m/2⌉` 个孩子**（至少 `⌈m/2⌉ - 1` 个关键字），保证节点别太"空"。
3. 所有叶子在**同一层**（天然平衡）。
4. 节点的关键字**有序**排列，且关键字之间夹着子树指针（左小右大）。

一个 3 阶（即 2-3 树）的示意：

```text
            [ 10 | 20 ]           一个节点存 2 个关键字、3 个孩子指针
           /     |      \
     (<10)  [10,20)   (>20)
```

高扇出（一个节点多个分叉）是 B 树的核心：**阶 m 越大，同样的 n 个 key 树高越低，磁盘 IO 次数越少**。

### 8.2 B+ 树：数据只存在叶子

B+ 树在 B 树基础上做了关键改造：

- **非叶子节点只存"索引 key + 孩子指针"，不存实际数据**；**所有真实数据（或数据行指针）只放叶子节点**。
- **所有叶子节点用链表（双向）横向相连**，形成一个有序链表。

```text
              [ 10 | 20 ]            非叶子：只索引，不存数据
             /     |      \
      [叶子]   [叶子]    [叶子]       每个叶子存真实记录
       1-9      10-19     20-29
        |         |         |
        +---->----+---->----+         叶子之间链表相连
```

### 8.3 为什么数据库 / 文件系统用 B+ 树而非二叉搜索树

| 原因 | 解释 |
| --- | --- |
| **高扇出，低树高** | 一个磁盘块能塞很多 key，树高通常只有 3~4 层，一次查询最多 3~4 次 IO |
| **更适合磁盘页** | 节点大小按磁盘页（如 16KB）对齐，一次 IO 读满一整页，利用率高 |
| **叶子链表利于范围查询** | B 树的数据散在各层，范围扫描要中序遍历整棵树；B+ 树叶子链表直接顺序扫，MySQL 的 `BETWEEN`、分页极快 |
| **非叶子纯索引更省空间** | 同样内存能缓存更多上层索引，命中率更高 |

**聚簇索引**一句话：InnoDB 的聚簇索引让 B+ 树的叶子节点直接存整行数据，表数据本身就是按主键排好序的 B+ 树，因此"按主键查"最快、范围查也顺带高效。

## 九、堆

堆（Heap）是一个**完全二叉树**，但它**不保证全序**（不能像 BST 那样中序升序），只保证"父节点与子节点的大小关系"，所以堆为"取最值"而生，而不是为"查找任意值"。

### 9.1 大顶堆 / 小顶堆

- **大顶堆（Max-Heap）**：每个节点的值 **≥ 它的孩子**，所以**根一定是最大值**。
- **小顶堆（Min-Heap）**：每个节点的值 **≤ 它的孩子**，所以**根一定是最小值**。

```text
大顶堆示例：
        [ 9 ]
       /     \
    [ 7 ]   [ 5 ]
   /   \    /
 [ 3 ] [ 4 ][ 2 ]         父 >= 子，根 9 最大
```

因为是完全二叉树，堆**几乎总是用数组存**（见第三节性质 5），不浪费空间且 Cache 友好。

### 9.2 两个核心调整：下沉与上浮

- **上浮（sift up / bubble up）**：在堆**末尾**插入新元素后，沿父链向上比较交换，直到父 ≥ 子（大顶堆）。用于**插入**。
- **下沉（sift down / heapify down）**：把**堆顶**元素弹出后，用最后一个元素补到堆顶，再自上而下与较大的孩子比较交换，直到恢复堆序。用于**删除堆顶**。

下沉（大顶堆）骨架：

```java
package cn.canoe.dsa.heap;

/** 大顶堆下沉调整（数组从 0 起）。 */
public class MaxHeapSift {
    void siftDown(int[] a, int n, int i) {
        while (true) {
            int largest = i;
            int l = 2 * i + 1;
            int r = 2 * i + 2;
            if (l < n && a[l] > a[largest]) largest = l;
            if (r < n && a[r] > a[largest]) largest = r;
            if (largest == i) break;          // 已满足堆序
            int t = a[i]; a[i] = a[largest]; a[largest] = t;
            i = largest;                       // 继续向下
        }
    }
}
```

### 9.3 PriorityQueue 与 Top-K 问题

Java 的 `PriorityQueue` 底层就是**小顶堆**（默认自然序升序，队首是最小元素）。它的 `offer` / `poll` 都是 O(log n)。

**Top-K 问题**（从 n 个数里找最大的 K 个）是堆的招牌应用：

```java
package cn.canoe.dsa.heap;

import java.util.ArrayDeque;
import java.util.Comparator;
import java.util.PriorityQueue;

public class TopK {
    /** 返回数组中最大的 k 个元素。 */
    int[] topK(int[] nums, int k) {
        // 小顶堆，容量固定为 k：堆顶是"当前 k 个最大里的最小者"
        PriorityQueue<Integer> minHeap =
            new PriorityQueue<>(Comparator.naturalOrder());
        for (int x : nums) {
            if (minHeap.size() < k) {
                minHeap.offer(x);
            } else if (x > minHeap.peek()) {
                minHeap.poll();
                minHeap.offer(x);
            }
        }
        int[] res = new int[k];
        int idx = 0;
        for (int x : minHeap) res[idx++] = x;
        return res;
    }
}
```

时间复杂度 `O(n log k)`，比先全排序 `O(n log n)` 更省，尤其当 `k << n`。

**堆排序**一句话：建堆（O(n) 自底向上 heapify）后，反复把堆顶（最大值）与末尾交换并缩小堆范围下沉，最终得到升序数组，时间复杂度 O(n log n)、原地、但**不稳定**。

## 本篇小结

- **树**描述"一对多"的层级关系，**深度看根、高度看叶**，叶子数 `n0 = n2 + 1` 是最常用性质。
- 满二叉树一定完全，但完全二叉树不一定满；**完全二叉树适合用数组顺序存储**（父子下标互算）。
- 链式存储用"左右指针"，通用不浪费空间；数组存储用"下标 2i/2i+1"，适合堆。
- **前/中/后序**差在"根的访问时机"，**中序遍历 BST 必得升序**，是验证 BST 合法性的关键。
- 层序遍历用**队列 BFS**，按层打包输出；前/中/后序可用递归（隐式栈）或显式栈迭代。
- 普通 **BST 查找 O(h)**，但有序插入会退化成链表 O(n)，所以必须引入平衡机制。
- **AVL** 严格平衡（平衡因子 ±1），查找 O(log n) 且最坏确定，但插入删除旋转重，适合读多写少。
- **红黑树**近似平衡（最长 ≤ 2×最短），插入删除旋转少，是 `TreeMap`、HashMap 桶、epoll、Linux 调度的底层。
- **B+ 树**高扇出、低树高、叶子链表相连，是数据库/文件系统减少磁盘 IO、做范围查询的首选。
- **堆**是完全二叉树数组存，分大/小顶堆，靠上浮/下沉维持，支撑 `PriorityQueue` 与 Top-K、堆排序。
