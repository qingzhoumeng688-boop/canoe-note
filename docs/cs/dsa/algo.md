## 一、递归（Recursion）

递归的本质是**"把大问题交给一个'长得一样但更小'的子问题去解决"**。函数自己调用自己，靠子问题的解拼出原问题的解。

### 1.1 自顶向下拆解

一个标准递归函数有三要素：

1. **终止条件（base case）**：最小的、能直接回答的子问题，防止无限递归。
2. **递归关系**：原问题如何用子问题的解表达（递推式）。
3. **向子问题推进**：参数必须是"更小/更接近终止"的。

以"求 n 的阶乘"为例：

```java
long factorial(int n) {
    if (n <= 1) return 1;        // base case
    return n * factorial(n - 1); // 子问题：n! = n * (n-1)!
}
```

再比如"求二叉树高度"，也是典型的自顶向下：`height(node) = 1 + max(height(left), height(right))`，空节点返回 0。

### 1.2 base case 防栈溢出

递归每一次调用都会在线程栈上压入一帧（参数、返回地址、局部变量）。如果 base case 写错或根本没有，调用链无限延长，就会 `StackOverflowError`。Java 默认栈深约几百到几千，递归过深（如阶乘算到几万）就危险。

经验：**凡是递归，先写 base case，再写递推**；若问题规模可能很大，考虑改成迭代或用记忆化（见第四篇动态规划）。这也呼应**第 01 篇复杂度**：递归深度直接决定空间复杂度 O(深度)，时间复杂度看"每层工作量 × 层数"。

### 1.3 递归转迭代 / 尾递归

有些递归可以写成循环，省掉调用栈。斐波那契"朴素递归"是反面教材——`fib(n) = fib(n-1)+fib(n-2)` 重复计算了指数级子问题，时间 O(2ⁿ)：

```java
// 朴素递归（慢，重复计算严重）
int fib(int n) {
    if (n < 2) return n;
    return fib(n - 1) + fib(n - 2);
}

// 改成迭代，O(n) 时间 O(1) 空间
int fibIter(int n) {
    if (n < 2) return n;
    int a = 0, b = 1;
    for (int i = 2; i <= n; i++) { int t = a + b; a = b; b = t; }
    return b;
}
```

**尾递归**：递归调用是函数的最后一步（如累加器版本），理论上编译器可优化成循环复用栈帧，但注意 Java **并不保证**做尾递归优化，真要压栈深还得手动改迭代。

## 二、分治（Divide & Conquer）

分治是递归思想的系统化：把问题分成若干**互不重叠**的子问题，各自解决后再合并。

### 2.1 三步法

- **分解（Divide）**：把原问题拆成规模更小的同类子问题。
- **解决（Conquer）**：子问题小到 base case 直接解，否则继续递归。
- **合并（Merge）**：把子问题的解合并成原问题的解。

### 2.2 归并排序与快速排序是典范

| 算法 | 分解方式 | 合并方式 | 平均复杂度 |
| --- | --- | --- | --- |
| **归并排序** | 数组从中间劈成两半 | 把两个有序半区 `merge` 成一个 | O(n log n) |
| **快速排序** | 选基准 `pivot`，按与基准的大小关系分成左右两区 | 无需显式合并，分区即有序 | O(n log n)（最坏 O(n²)） |

归并排序的 `merge` 是典型合并步骤（详见**第 05 篇排序**）；快排的分区让基准就位。二者都是"先分后治"，且都依赖递归。

归并排序核心：先递归分到底，再合并两个有序段：

```java
void mergeSort(int[] a, int l, int r) {
    if (l >= r) return;
    int mid = (l + r) >> 1;
    mergeSort(a, l, mid);
    mergeSort(a, mid + 1, r);
    int[] tmp = new int[r - l + 1];
    int i = l, j = mid + 1, k = 0;
    while (i <= mid && j <= r) tmp[k++] = a[i] <= a[j] ? a[i++] : a[j++];
    while (i <= mid) tmp[k++] = a[i++];
    while (j <= r) tmp[k++] = a[j++];
    System.arraycopy(tmp, 0, a, l, tmp.length);
}
```

快速排序核心：分区让基准归位，再递归两侧：

```java
void quickSort(int[] a, int l, int r) {
    if (l >= r) return;
    int pivot = a[l], i = l, j = r;
    while (i < j) {
        while (i < j && a[j] >= pivot) j--;
        a[i] = a[j];
        while (i < j && a[i] <= pivot) i++;
        a[j] = a[i];
    }
    a[i] = pivot;
    quickSort(a, l, i - 1);
    quickSort(a, i + 1, r);
}
```

### 2.3 适用条件与和递归的关系

分治能用的前提：

1. 问题能分解成同构子问题；
2. 子问题相互独立（不重叠）；
3. 子问题解能高效合并。

**与递归的关系**：分治几乎总是用递归实现（因为"子问题同构"天然契合自调用），但递归不一定是分治——比如线性递归遍历链表就不是分治（没有"合并多个子结果"）。反之，若子问题**有重叠**，那就该用动态规划而非裸分治（见第四篇）。

## 三、贪心（Greedy）

贪心算法的策略很直接：**每一步都做当前看起来最优的选择，并且从此不再反悔**，期望最后得到全局最优。

### 3.1 正确性需要证明

贪心"想得美"，但**不是所有问题都能贪**。要用贪心，必须证明"局部最优能推出全局最优"。最常用的方法是**交换论证（Exchange Argument）**：假设存在一个最优解和贪心解不同，通过把最优解里的某一步换成贪心的选择，证明不会变差，从而说明贪心解也是最优的。

### 3.2 典型例题

| 问题 | 贪心策略 | 直觉 |
| --- | --- | --- |
| **活动选择** | 每次选"结束时间最早"且不与已选冲突的活动 | 早结束留出更多时间给后面 |
| **零钱（特定面额）** | 面额是倍数关系时，每次用"不超过剩余金额的最大面额" | 如 1/5/10/25，贪心即最优 |
| **霍夫曼编码** | 每次合并频率最小的两个节点 | 高频字符短编码，总长度最小 |

注意零钱问题**并非总是能贪**：若面额为 `[1, 3, 4]`，要凑 6，贪心会取 4+1+1=3 枚，但最优是 3+3=2 枚。所以"特定面额"才能贪心，一般零钱要用动态规划。

活动选择的贪心实现（按结束时间排序后线性扫描）：

```java
import java.util.Arrays;
import java.util.Comparator;

int activitySelection(int[][] acts) { // acts[i] = {start, end}
    Arrays.sort(acts, Comparator.comparingInt(a -> a[1]));
    int count = 0, lastEnd = -1;
    for (int[] a : acts) {
        if (a[0] >= lastEnd) { count++; lastEnd = a[1]; } // 不冲突就选
    }
    return count;
}
```

### 3.3 贪心 vs 动态规划

| 维度 | 贪心 | 动态规划 |
| --- | --- | --- |
| **决策** | 每步只选当前最优，不回头 | 考虑所有子问题，选全局最优 |
| **能否反悔** | 不能 | 通过状态转移间接"反悔" |
| **适用** | 有贪心选择性质的问题 | 有重叠子问题+最优子结构 |
| **复杂度** | 通常更低（一维扫描） | 通常更高（要填表） |

一句话区分：**能证明"局部最优 ⇒ 全局最优"就用贪心（更快）；证明不了就上 DP**。

## 四、动态规划（Dynamic Programming）

动态规划是面试权重最高、也最考验"建模"能力的一类思想。

### 4.1 两个特征

- **重叠子问题（Overlapping Subproblems）**：不同决策会反复计算同一个子问题（如朴素斐波那契）。DP 用"记下来"消除重复。
- **最优子结构（Optimal Substructure）**：问题的最优解包含子问题的最优解，于是可以"由小推大"。

### 4.2 四步建模

1. **定义状态**：`dp[i]` 或 `dp[i][j]` 表示"什么情况下的最优值"。
2. **写转移方程**：`dp[...]` 如何用更小的状态表达。
3. **定边界/初始化**：base case 对应的 dp 值。
4. **确定遍历顺序**：自底向上填表，或自顶向下记忆化搜索。

### 4.3 自底向上 vs 记忆化搜索

- **自底向上（迭代填表）**：从最小状态算到目标，`for` 循环填 `dp` 数组，没有递归栈开销，工程常用。
- **记忆化搜索（Top-down）**：按递归写法，用 `HashMap`/`数组` 缓存已算结果，代码更直观，等价于自底向上但多了函数调用。

记忆化斐波那契（消灭重复计算，O(n)）：

```java
int fibMemo(int n, int[] memo) {
    if (n < 2) return n;
    if (memo[n] != 0) return memo[n];        // 已算过直接取
    return memo[n] = fibMemo(n - 1, memo) + fibMemo(n - 2, memo);
}
```

**空间优化（滚动数组）**：很多 DP 当前行只依赖上一行（如背包、LCS），可以把二维 `dp[i][j]` 压缩成一维 `dp[j]`，按正确顺序覆盖，空间从 O(n²) 降到 O(n)。

### 4.4 表格展示：0-1 背包填表

问题：容量 `W=4`，有 3 件物品（重量/价值）：`(w,v) = (1,1), (2,2), (3,3)`，`dp[i][j]` 表示前 i 件、容量 j 时的最大价值。转移：`dp[i][j] = max(dp[i-1][j], dp[i-1][j-w_i] + v_i)`。

```text
物品\容量   j=0  j=1  j=2  j=3  j=4
 初始(0)    0    0    0    0    0
 物品1(1,1)  0    1    1    1    1
 物品2(2,2)  0    1    2    3    3
 物品3(3,3)  0    1    2    3    4
```

解读：处理到物品3、容量4时，`max(dp[2][4]=3, dp[2][1]+3=1+3=4)` = 4，即选物品1+物品3，总重 1+3=4、价值 4。填表过程就是"逐行扫描，能装就比较装/不装"。

## 五、经典 DP 题

### 5.1 0-1 背包（见上表）

每件物品选或不选，目标在容量内价值最大。一维滚动写法：

```java
int knapsack(int[] w, int[] v, int W) {
    int[] dp = new int[W + 1];         // dp[j] = 容量 j 时最大价值
    for (int i = 0; i < w.length; i++)
        for (int j = W; j >= w[i]; j--) // 逆序，避免同件重复选
            dp[j] = Math.max(dp[j], dp[j - w[i]] + v[i]);
    return dp[W];
}
```

逆序遍历是关键：它保证更新 `dp[j]` 时引用的 `dp[j-w[i]]` 还是"上一轮（没选第 i 件）"的值。

### 5.2 最长公共子序列 LCS

`dp[i][j]` = 文本 A 前 i 字符与 B 前 j 字符的 LCS 长度。若 `A[i]==B[j]` 则 `dp[i][j]=dp[i-1][j-1]+1`，否则 `dp[i][j]=max(dp[i-1][j], dp[i][j-1])`。和"最长公共子串"（要求连续）不同，LCS 不要求连续。

```java
int lcs(String a, String b) {
    int n = a.length(), m = b.length();
    int[][] dp = new int[n + 1][m + 1];
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= m; j++)
            dp[i][j] = a.charAt(i - 1) == b.charAt(j - 1)
                ? dp[i - 1][j - 1] + 1
                : Math.max(dp[i - 1][j], dp[i][j - 1]);
    return dp[n][m];
}
```

### 5.3 最长递增子序列 LIS

`dp[i]` = 以第 i 个元素结尾的 LIS 长度，转移 `dp[i] = max(dp[j]+1)` 对所有 `j<i 且 a[j]<a[i]`。优化版用"耐心排序/二分"可把 O(n²) 降到 O(n log n)：维护一个 tails 数组，每个新元素二分插入。

```java
int lengthOfLIS(int[] a) {
    int[] tails = new int[a.length];
    int size = 0;
    for (int x : a) {
        int lo = 0, hi = size;
        while (lo < hi) { int mid = (lo + hi) >> 1; if (tails[mid] < x) lo = mid + 1; else hi = mid; }
        tails[lo] = x;
        if (lo == size) size++;
    }
    return size;
}
```

### 5.4 编辑距离（Levenshtein）

`dp[i][j]` = A 前 i 字符变到 B 前 j 字符的最少操作（插入/删除/替换）。`A[i]==B[j]` 时 `dp[i][j]=dp[i-1][j-1]`；否则取"插入/删除/替换"三者最小值 +1。这是"字符串相似度"的基石。

### 5.5 入门两题

| 题目 | 状态与转移 |
| --- | --- |
| **爬楼梯** | `dp[i] = dp[i-1] + dp[i-2]`，即第 i 级来自 i-1 跨一步或 i-2 跨两步（本质是斐波那契） |
| **打家劫舍** | `dp[i] = max(dp[i-1], dp[i-2] + nums[i])`，偷当前就不能偷上一户 |

这两题是理解"状态定义 + 转移"的最好起点，建议先吃透再啃背包/LCS。

## 六、回溯（Backtracking）

回溯 = **DFS（深度优先搜索）+ 剪枝**。它系统地尝试所有可能的选择，走到死胡同就"回退一步换条路"，本质上是在解空间树上搜索。

### 6.1 试错—回退

通用框架：

```java
void backtrack(路径, 选择列表) {
    if (满足结束条件) { 记录解; return; }
    for (每个可选选择) {
        if (不合法 / 剪枝条件) continue;
        做选择;            // 加入路径
        backtrack(新路径, 新选择列表);
        撤销选择;          // 回溯的关键：恢复现场
    }
}
```

"撤销选择"是回溯区别于普通 DFS 的核心：它让你在返回上一层后能尝试别的分支，状态保持干净。

### 6.2 ASCII 图：全排列与 N 皇后的搜索树

全排列 `[1,2,3]`（每步从"还没用过的数"里挑一个），深度优先、用完回溯：

```text
                 [ ]
        /         |         \
      1           2           3
     / \         / \         / \
   12   13     21   23     31   32
   /     \     /     \     /     \
 123    132  213    231  312    321   <- 叶子即完整排列
```

N 皇后（4 皇后示例，每行放一个皇后，列/对角线冲突则剪枝）：

```text
行1放第1列 -> 行2只能放第3列 -> 行3无合法列(剪枝, 回溯)
           -> 行2放第4列 -> 行3放第2列 -> 行4放第3列  => 一个解
行1放第2列 -> ...（另一棵子树）
```

搜索树会在"行2放第1列导致行3无处可放"的分支上被剪掉，避免无效深入。回溯求的是**所有解/可行解**，这是它和 DP 的根本区别。

### 6.3 回溯代码：全排列

```java
void permute(int[] nums, boolean[] used, List<Integer> path, List<List<Integer>> res) {
    if (path.size() == nums.length) { res.add(new ArrayList<>(path)); return; }
    for (int i = 0; i < nums.length; i++) {
        if (used[i]) continue;
        used[i] = true; path.add(nums[i]);
        permute(nums, used, path, res);      // 递归
        path.remove(path.size() - 1); used[i] = false; // 撤销选择
    }
}
```

N 皇后合法性判断用"列 + 两条对角线"三个集合记录已占位置，每行尝试放一个不冲突的列即可，结构同上面的框架。

### 6.4 回溯 vs 动态规划

| 维度 | 回溯 | 动态规划 |
| --- | --- | --- |
| **目标** | 找出所有/某个可行解 | 求最优值（最大/最小/存在性计数） |
| **方式** | DFS + 剪枝，穷举搜索 | 状态转移，由小推大 |
| **代价** | 往往指数级，靠剪枝收敛 | 多项式级（多数情况） |
| **典型** | 全排列、N 皇后、子集、数独 | 背包、LCS、最短路径 |

一句话：**要"把所有解都列出来"用回溯；要"最优值是多少"用 DP**。

## 七、双指针与滑动窗口

双指针是降低复杂度的高频技巧，核心是两个索引协同移动，把 O(n²) 降到 O(n)。

### 7.1 左右指针

常见于"有序数组的两数之和""反转数组""盛水容器"：一头一尾向中间夹逼，根据条件决定哪边动。

```java
// 有序数组找两个数和为 target
boolean twoSum(int[] a, int target) {
    int l = 0, r = a.length - 1;
    while (l < r) {
        int s = a[l] + a[r];
        if (s == target) return true;
        else if (s < target) l++; // 太小，左指针右移增大
        else r--;                  // 太大，右指针左移减小
    }
    return false;
}
```

### 7.2 滑动窗口

用一个"可变长度的窗口 `[l, r]`"在数组上滑动，维护窗口内的某种性质（如无重复字符）。右指针扩张、左指针在违反条件时收缩，把"所有子区间"的枚举从 O(n²) 降为 O(n)。

最长无重复字符子串（窗口内字符不重复，用布尔/计数数组判断）：

```java
int longestNoRepeat(String s) {
    boolean[] seen = new boolean[128];
    int l = 0, max = 0;
    for (int r = 0; r < s.length(); r++) {
        char c = s.charAt(r);
        while (seen[c]) { seen[s.charAt(l)] = false; l++; } // 收缩到不含 c
        seen[c] = true;
        max = Math.max(max, r - l + 1);
    }
    return max;
}
```

| 问题 | 窗口维护什么 |
| --- | --- |
| **最长无重复子串** | 窗口内字符不重复，`l` 遇到重复就右移跳过 |
| **最小覆盖子串** | 窗口包含目标所有字符后，尽量左移 `l` 缩短 |

这关联到**第 02 篇（数组/双指针）**与**第 04 篇（哈希表做字符计数）**：窗口合法性常用哈希/数组计数来判断。

## 八、位运算技巧

位运算在算法里常用来做"状态压缩"和"去重"，速度快且写法巧妙。

- **异或去重**：`a ^ a = 0`、`a ^ 0 = a`，且异或满足交换律。所以"一个数组里除一个数出现一次、其余都出现两次"，全体异或一遍，结果就是那个落单的数（见 LeetCode 136）。更进一步，若有两个落单数，全体异或得到 `x^y`，按某一位是 1 把数分成两组分别异或即可分开二者。
- **lowbit**：`x & (-x)` 取最低位的 1，用于树状数组（见本系列第 09 篇）和"枚举子集/判断奇偶"。
- **状态压缩 DP 一句话**：当"约束集合"规模小（如 ≤ 20），可用一个整数的二进制位表示"某元素是否已选"，把子集/排列状态压成 `dp[mask]`，把组合枚举转成位操作，常见于旅行商 TSP、铺砖等题。

补几个常用技巧：落单数字用异或一行解决；`n & (n-1)` 可把最低位 1 清零（判断 2 的幂：`n>0 且 n&(n-1)==0`）；`(n >> k) & 1` 取第 k 位。

```java
// 落单的数：其余都出现两次，只有一个出现一次
int singleNumber(int[] a) {
    int x = 0;
    for (int v : a) x ^= v; // 成对抵消，剩下落单数
    return x;
}
```

## 本篇小结

- **递归**：三要素为 base case、递推关系、向更小子问题推进；base case 写错会 `StackOverflow`。
- **递归深度**：决定空间复杂度，朴素斐波那契 O(2ⁿ) 应改成迭代；Java 不保证尾递归优化。
- **分治**：三步为分解-解决-合并，归并/快排是典范；子问题有重叠时应改 DP 而非裸分治。
- **贪心**：每步取局部最优且不再反悔，正确性需证明（交换论证），零钱问题并非总能贪。
- **贪心 vs DP**：能证"局部最优⇒全局最优"用贪心（更快），否则用 DP。
- **动态规划**：两特征为重叠子问题 + 最优子结构；建模四步：状态、转移、边界、遍历顺序。
- **DP 写法**：有自底向上填表与记忆化搜索两种，滚动数组可做空间优化（如背包压成一维）。
- **回溯**：= DFS + 剪枝，靠"撤销选择"回退，求所有/可行解；DP 求最优值，这是二者根本区别。
- **双指针/位运算**：双指针与滑动窗口把 O(n²) 降到 O(n)，窗口合法性常借哈希计数；位运算擅长去重与状态压缩。
- **刷题路线**：按"数组→链表→哈希→栈堆→树→图→回溯→DP→高级结构"推进，卡壳回看本系列对应篇章。
